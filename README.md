A work-in-progress UCI [shatranj] engine based on [Stormphrax], with NNUE evaluation trained from zero knowledge starting with random weights.

The oranj project prides itself on using self-generated training data for its networks, and will never use data generated by a third party. This repo contains no LLM-generated code.

Supersedes [Stormphranj].

## UCI options
| Name                          |  Type   | Default value |  Valid values   | Description                                                                                                              |
|:------------------------------|:-------:|:-------------:|:---------------:|:-------------------------------------------------------------------------------------------------------------------------|
| `Hash`                        | integer |      64       |  [1, 67108864]  | Memory allocated to the transposition table (in MiB).                                                                    |
| `ClearHash`                   | button  |      N/A      |       N/A       | Clears all internal state, equivalent to sending `ucinewgame`.                                                           |
| `Threads`                     | integer |       1       |    [1, 2048]    | Number of threads used to search.                                                                                        |
| `MultiPV`                     | integer |       1       |    [1, 256]     | Number of lines to search at once.                                                                                       |
| `Contempt`                    | integer |       0       |  [-1000, 1000]  | Offset applied to all evals - roughly how bad a position oranj will accept to avoid drawing.                             |
| `UCI_ShowWDL`                 |  check  |    `true`     | `false`, `true` | Whether oranj displays predicted win/draw/loss probabilities in UCI output.                                              |
| `EvalSharpness`               | integer |      100      |   [100, 120]    | Power (*100) that scores are raised to for display.                                                                      |
| `ShowCurrMove`                |  check  |    `false`    | `false`, `true` | Whether oranj starts printing the move currently being searched after a short delay.                                     |
| `MoveOverhead`                | integer |      10       |   [0, 50000]    | Amount of time oranj assumes to be lost to overhead when making a move (in ms).                                          |
| `SoftNodes`                   |  check  |    `false`    | `false`, `true` | Whether oranj will finish the current depth after hitting the node limit when sent `go nodes`.                           |
| `SoftNodeHardLimitMultiplier` | integer |     1678      |    [1, 5000]    | With `SoftNodes` enabled, the multiplier applied to the `go nodes` limit after which oranj will abort the search anyway. |
| `Minimal`                     |  check  |    `false`    | `false`, `true` | Whether to avoid printing any info during search other than the final line.                                              |

## Builds
`avx512`: requires BMI2, AVX-512, VNNI and VBMI2 (Zen 4/Ice Lake and up)  
`avx2-bmi2`: requires BMI2 and AVX2 and assumes fast `pext` and `pdep`  
`zen2`: requires BMI and AVX2, but doesn't assume fast `pext` and `pdep` - if you have an older AMD CPU (3000-series Ryzen or earlier), you want this one  
`apple-m1`: for Apple silicon devices  
`armv8-4`: ARMv8.4-a. requires NEON with dotprod

Alternatively, build the makefile target `native` for a binary tuned for your specific CPU (see below)  

### Note:  
- If you have an AMD Zen 1 (Ryzen x 1xxx), Zen+ (Ryzen x 2xxx) or Zen 2 (Ryzen x 3xxx) CPU, use the `zen2` build even though your CPU supports BMI2. These CPUs implement the BMI2 instructions `pext` and `pdep` in microcode, which makes them unusably slow for oranj's purposes.

## Building
Requires Make, Clang and LLD.
```bash
> make <BUILD>
```
- replace `<BUILD>` with the binary you wish to build - `native`/`avx512`/`avx2-bmi2`/`zen2`/`armv8-4`
  - if not specified, the default build is `native`
- if you wish, you can have oranj include the current git commit hash in its UCI version string - pass `COMMIT_HASH=on`

oranj includes optimisations for NUMA machines on Linux via libnuma, which can be enabled by passing `USE_LIBNUMA=on`. This is useful when running one instance of oranj with many threads across multiple NUMA nodes. Running multiple instances of oranj compiled with this option is not recommended.
